# 概要 (Overview)

Ghidra Bridge は、実行中の Ghidra プログラムへのネットワークアクセスを提供します。
本ブリッジは WebSocket JSON-RPC 2.0 と MCP Streamable HTTP `2026-07-28` の 2 つのネットワークトランスポートをサポートします。
レジストリは `interface.get` から `batch.execute` まで 53 個の公開ドット記法メソッドを定義します。
WebSocket は 53 個すべてを提供し、MCP は 52 個を提供します（`interface.get` は WebSocket 専用）。
ランタイム JAR はサードパーティ製ライブラリへの依存が一切ありません。

## 設計目標

- **単一カタログ**: すべての操作、スキーマ、ハンドラーは型付けされた 1 つのメソッドレジストリで管理されます。
- **トランスポート間の対称性**: WebSocket と MCP は、パラメータ、戻り値、エラー形式、検証ルールを共有します。
- **外部依存の排除**: コアランタイムおよびトランスポートは標準の Java 21 プラットフォームライブラリのみを使用します。
- **厳格な分離**: Ghidra 固有の API は、アダプターモジュールのサービスインターフェース配下に完全に隠蔽されます。

## 並行性とセッションモデル

ブリッジは 1 セッションにつき 1 つのアクティブな Ghidra プログラムにバインドします。
リクエストは単一のディスパッチキュー内で順番に実行されます。
ディスパッチャは一度に 1 つの操作のみを実行します。

Ghidra のバックグラウンド解析は独立したスレッドで実行されます。
解析実行中:
- 読み取り操作は継続して利用可能です。
- 変更操作は HTTP ステータス `409` およびエラーコード `analysis_in_progress` を返します。
- 新たな解析の開始はステータス `409` およびエラーコード `analysis_already_running` を返します。

## 共通のリクエストパターン

各メソッドは、双方のトランスポートで共通の標準リソースパターンに従います:

- **取得と削除 (Get/Delete)**: アドレスや識別子などの `selector` オブジェクトを指定します。
- **更新 (Update)**: `selector` オブジェクトと変更フィールドを含む `patch` オブジェクトを指定します。
- **作成 (Create)**: 初期属性を含む `resource` オブジェクトを指定します。
- **一覧取得 (List)**: 任意の `filter` オブジェクトと、取得件数制限 `limit` および不透明な `cursor` 文字列を持つ任意の `page` オブジェクトを受け取ります。
- **フィールド射影 (Projection)**: 戻り値のプロパティを絞り込むため、任意の `projection.fields` 配列を受け取ります。

## 有界アドレススキャン

アドレス順のスキャン操作は、メモリ項目を協調的に検査します。
対象となる一覧取得操作:
- `code_unit.list`
- `data_unit.list`
- `instruction.list`
- `function.list`
- `global_variable.list`
- `symbol.list`
- `comment.list`
- `flow_override.list`

スキャン操作は `scan` オブジェクトを受け取ります。
`scan.range` オブジェクトで `start` と `end` アドレスを指定します。
`scan.timeout_ms` は 100 〜 60000 ミリ秒の制限です（デフォルトは 1000 ミリ秒）。

レスポンスには `scan` メタデータブロックが含まれます:

```json
{
  "items": [],
  "next_cursor": "eyJ...",
  "scan": {
    "kind": "address",
    "requested_start": "ram:00100000",
    "requested_end": "ram:001fffff",
    "scanned_start": "ram:00100000",
    "scanned_end": "ram:0017ffff",
    "complete": false,
    "stop_reason": "timeout",
    "elapsed_ms": 1000
  }
}
```

`stop_reason` は `completed`、`limit`、または `timeout` を返します。
一致する項目が 0 件であっても、未完了のスキャンは `next_cursor` を返します。
呼び出し元はこの値を `page.cursor` として渡し、前回中断した位置からスキャンを再開できます。

## グローバル変数とデータの同期

`global_variable` 関連メソッドは、定義済みデータとプライマリラベルを整合的に管理します。
変数の作成や更新には、アドレス、名前、および構造化データ型参照が必要です。
変更操作が命令や無関係な定義済みデータを上書きすることはありません。
グローバル変数を削除するとデータ定義は解除されますが、ラベルは明示的に指定しない限り保持されます。
